# Hide and Seek — Phase 3.6

広い夕暮れ公園で、2体の赤鬼から隠れ、仲間を救出するスマホ向けWebゲーム。正式ベースのPhase 3.5から、音声・ミニマップ・満員通知だけを修正しています。中断前の実装を引き継ぎました。

## 起動・GitHub Pages

このフォルダーで `python -m http.server 8000` を実行し、`http://localhost:8000` を開きます。HTMLのダブルクリックではモジュールとPWAが動きません。

ZIPの**中身をリポジトリ直下**へ配置します。`index.html`、各JS、CSS、`sw.js`、manifest、`icons/`、**`audio/`** をまとめてアップロードしてください。GitHubの Settings → Pages で `main` / `(root)` を指定します。ビルドやパッケージのインストールは不要です。リポジトリ名付きURLでも動く相対パス構成です。

Android Chromeで公開URLを開き、「ホーム画面に追加」または「アプリをインストール」。初回の全資産キャッシュ完了後は、音源を含めてオフライン起動できます。キャッシュ名は `hide-seek-phase36-v2` に更新しています。旧版を開いている場合は、一度すべて閉じて開き直してください。公開時は古いファイルと新しいファイルを混在させず、`audio/` も含めて置き換えます。

## 操作

1. 1分・3分・5分を選んでスタート。BGMはこのタップから始まります。
2. 青い帽子の「操作中」キャラを操作。光る地点をタップすると自動で歩きます。
3. 画面をなぞって見渡し、全体図をタップして見る場所を切り替えます。「操作中へ」で追従へ戻します。下の場所一覧からも移動できます。
4. 隠れ場所は1人用。先客がいたら頭上に「！」が出て0.6秒停止し、それから別の場所へ歩きます。
5. 牢屋の鍵マークへ到着すると捕まった仲間を全員救出。操作キャラが捕まると生存者へ自動交代し、救出後も現在の操作を維持します。
6. 鬼の正面を避けましょう。フォーカス中は移動途中でも1回だけ行き先を変更できます。正式に発見されると鬼が追跡し、接近して捕獲します。

時間切れまで1人でも残れば成功、全員捕獲で敗北。スロー中も制限時間は通常どおり進みます。一時停止・再スタート・タブを離れたときの自動停止を維持しています。

## Phase 3.6の修正

### 音声

旧版は4曲を一括で待ち、1曲の失敗で全BGMを使用不能にしていました。「再読込」も表示だけで、失敗した読み込みを再実行していませんでした。

各曲の状態を独立して管理し、ブラウザ標準のHTMLAudioElementでMP3を再生します。START・ON・再試行タップ内で `play()` を呼び、同じタップで心音用AudioContextも `resume()` します。ページ読込直後の自動再生には依存しません。音源パスは `import.meta.url` を基準に解決します。

| 場面 | 提供音源 | 内部名 | 音量係数 |
|---|---|---|---:|
| 通常 | みどりの公園.mp3 | audio/park.mp3 | 0.36 |
| 危険 | サビついたカギ.mp3 | audio/danger.mp3 | 0.43 |
| 発見 | 驚く.mp3 | audio/spotted.mp3 | 0.65 |
| 捕獲 | ショック1.mp3 | audio/captured.mp3 | 0.80 |

4ファイルは提供原本と同一です。日本語名の問題を避けるASCII名はPhase 3.5から維持しています。MP3本体の音量加工はありません。

- 通常・危険曲はループ。0.65秒のクロスフェード、最大危険度判定、危険解除1.8秒のヒステリシスを維持。
- 片方のBGMが失敗したときは、正常なもう片方を流します。失敗したSEがBGMを止めることもありません。
- 発見SE・捕獲SEは状態遷移時に1回。最後の捕獲SEはリザルト移行でも最後まで再生。
- **🔊 BGM ON / 🔇 BGM OFF** でBGM・SE・心音をまとめて切り替えます。ON復帰は現在の状態に合う曲へ。設定をlocalStorageへ保存する処理はなく、起動時はONです。
- 失敗したときだけ「音が出ないときはここをタップ」が出ます。タップすると失敗した音源を作り直して再ロード・再生し、成功するとボタンが消えます。
- 心音用Web Audioが使えない環境でも、BGMと提供SEは標準の音声再生で動作します。

音声出力は実ブラウザで非ゼロの音声信号まで確認しています。Android実機のスピーカー・音量設定・聴感と、今回の不具合が起きた公開URLの通信状態はこの環境では確認できません。確認範囲は `VALIDATION.md` に記載しました。

### ミニマップ

背景と地図レイヤーを透過し、操作キャラが上部のミニマップ領域へ来たら反対側へ移します。再移動まで2秒待つため、短い往復ではバタつきません。タップ判定も実際の表示位置に追従します。カメラ本体・表示倍率は変更していません。

### 満員時の通知

本当に定員1人の地点に先客がいた場合だけ、大きな「！」を頭上に表示し、そのキャラを実時間で0.6秒停止します。鬼・他のキャラ・時計は動き続けます。その後、既存の近くの空き地点／直前の地点／広場への徒歩退避を続けます。COMにも同じ演出を適用。経路エラーや捕獲には満員の「！」を付けません。

## 維持したもの

世界560×800、表示420×600、Canvas840×1200、16地点、遊具配置、移動速度、鬼2体の独立AI、遮蔽物で切り取る視野、視線判定、フォーカス、定員、COM、救出、操作交代、カメラ、時間選択を維持しています。

正式ベースのPhase 3.5には救出ルール1種類があり、ノーマル／サバイバル／レスキューの選択UIはありません。今回も未存在のモードは追加していません。救出無効のルール差替えと、サバイバル向け `lateOniAt` の3体目追加フックを維持しています。

## 検証の再実行

Node.js環境で `npm test`。ロジックテストに外部依存はありません。

ブラウザテストを実行する場合は `npm install --no-save playwright`、`npx playwright install chromium` の後、`node tests/browser.test.mjs`、`node tests/audio-browser.test.mjs` を実行します。音声テストは実MP3の再生結果をメーターで確認し、故障注入と再試行も検証します。計測やQA参照はテスト用サーバーだけが注入し、完成ゲームにデバッグUIはありません。

`engine.js` はゲーム状態、`camera.js` は表示座標、`sound.js` は音声、`app.js` はUIを担当します。ルールを差し替える構造は従来どおりです。アカウント・広告・解析・ユーザー情報の外部送信はありません。
